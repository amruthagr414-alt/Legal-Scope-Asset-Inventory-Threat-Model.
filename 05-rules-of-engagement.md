# 5. Rules of Engagement

## 5.1 Purpose

These rules define how the proposed local lab assessment is to be conducted safely, ethically, and within the approved scope.

## 5.2 Roles and responsibilities

| Role | Responsibility |
|---|---|
| Lab owner | Maintains the local environment and approves scope |
| Student assessor | Follows the scope, records observations, and protects evidence |
| Supervisor / reviewer | Reviews the plan and receives escalations, if assigned |

## 5.3 Testing window

- Testing may occur only during a period approved by the lab owner or supervisor.
- Record the actual start and end time in the activity log.
- Do not run tests unattended.
- Stop the lab when the approved session ends.

## 5.4 Permitted activities

- Review application configuration and security settings.
- Review authentication and authorization design using designated test accounts.
- Observe application behavior using synthetic data.
- Review logs generated by the local lab.
- Document risks and recommend defensive mitigations.

## 5.5 Prohibited activities

- Testing any external or third-party system.
- Scanning public IP addresses or unrelated network ranges.
- Using real personal, financial, or institutional data.
- Destructive testing, service disruption, persistence, or data exfiltration.
- Publishing credentials, tokens, private logs, or sensitive screenshots.
- Expanding scope without renewed written authorization.

## 5.6 Evidence handling

- Capture only the minimum screenshots or notes needed to demonstrate the work.
- Redact credentials, tokens, personal data, and private configuration values.
- Store working evidence in a private local folder.
- Review all files before committing them to a public GitHub repository.
- Record the date, activity, asset, and observation for each evidence item.
- Do not claim a finding unless it was actually observed and documented.

## 5.7 Escalation procedure

If an unexpected issue occurs:
1. Stop the activity.
2. Avoid further interaction with the affected component.
3. Preserve only safe, non-sensitive observations.
4. Notify the lab owner or assigned supervisor.
5. Resume only after the scope and safety concern are reviewed.

## 5.8 Stop conditions

Stop immediately if:
- The target appears to be outside the approved local lab.
- The application or host becomes unstable.
- Unexpected access to external systems occurs.
- Real personal or confidential data appears.
- A test could disrupt another user's service or device.
- The owner or supervisor withdraws authorization.
